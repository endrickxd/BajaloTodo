## 2024-05-24 - [Fix SSRF bypass via redirects]
**Vulnerability:** The application fetches media using external URLs directly obtained from the Cobalt API response using `requests.get()` without validating the destination IP. This exposes the server to Server-Side Request Forgery (SSRF) vulnerabilities, especially given `requests.get()` follows HTTP redirects by default, potentially allowing bypass of initial URL string validation by pointing to internal network addresses or metadata services.
**Learning:** Even if the initial Cobalt API endpoints are hardcoded, the parsed `download_url` is untrusted. Mitigating SSRF requires rigorous application-layer IP validation. However, simply checking the hostname is insufficient due to DNS Rebinding attacks. Checking IPs using `socket.getaddrinfo` helps, but the inherent Time-of-Check to Time-of-Use (TOCTOU) limitation means the underlying IP could still change between validation and retrieval. Also, proper SSRF mitigation in Python requires inspecting and securely handling HTTP redirects manually since standard libraries follow them automatically. Additionally, when using `ipaddress` for IP validation, checking `getattr(ip, 'ipv4_mapped', None)` is critical to prevent IPv4-mapped IPv6 address bypasses without breaking standard IPv4 logic.
**Prevention:** Always validate external URLs and their resolved IPs against restricted ranges (private, loopback, multicast, link-local, unspecified) before fetching. Utilize secure HTTP client wrappers that disable automatic redirects and manually validate each location header in the redirect chain using `urllib.parse.urljoin`. Document the TOCTOU limitations associated with DNS-based validation when network-layer firewall restrictions (like network egress filtering) are not possible.
