## 2024-10-08 - [CRITICAL] Application-Layer SSRF Validation and DNS Rebinding
**Vulnerability:** The application fetches external URLs (e.g., from Cobalt API endpoints) using `requests.get()` without explicit validation, which can allow an attacker to make requests to internal infrastructure, leading to SSRF (Server-Side Request Forgery). Furthermore, `requests.get()` automatically follows redirects to potentially internal URLs, bypassing superficial initial validation.
**Learning:** We implemented application-layer IP validation using `socket.getaddrinfo()` to block restricted IP ranges (private, loopback, link-local, multicast). We iterated through all returned IPs. However, we documented an inherent Time-of-Check to Time-of-Use (TOCTOU) DNS rebinding limitation when using `socket.getaddrinfo()` for validation, as the underlying IP may change between the validation check and the actual `requests.get()` retrieval.
**Prevention:** To prevent the immediate SSRF risk, handle redirects manually (`allow_redirects=False`) and validate the hostname at each redirect step. For a complete defense against DNS rebinding, validation would ideally happen at the network/socket level, resolving the IP once and connecting directly to it (or via a proxy).
