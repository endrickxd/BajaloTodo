## 2024-10-16 - Prevent SSRF with explicit URL validation and manual redirect handling
**Vulnerability:** External APIs like Cobalt return URLs (tunnels or redirects) which the application previously fetched blindly using `requests.get()`. An attacker could exploit this by making the Cobalt instance (or by running a malicious Cobalt API) return a URL pointing to internal network IP addresses (like localhost or cloud metadata services) and the application would fetch it.
**Learning:** `requests.get()` automatically follows redirects. Validating only the initial URL is insufficient since an attacker can set up a redirect to an internal IP. We must validate IPs before making a request, and manually handle redirects to validate each subsequent URL in the chain against restricted IP ranges (Private, Loopback, Link Local, etc.). Also, using `socket.getaddrinfo` allows fetching all mapped IPs for a hostname to validate them, though this doesn't fully eliminate the TOCTOU DNS rebinding risk. We also learned how to explicitly extract `ipv4_mapped` without causing AttributeError for standard IPv4 objects in python's `ipaddress` library.
**Prevention:** Implement an `is_safe_url` function to resolve the hostname and check against restricted IPs before executing the request. Use `allow_redirects=False` in requests, and manually resolve next URLs using `urllib.parse.urljoin`, validating each step.
