## 2024-05-24 - [Fix Server-Side Request Forgery (SSRF) in external url fetch]
**Vulnerability:** The application fetches external files provided by the cobalt API using `requests.get(download_url)` directly without any IP validation. This allows an attacker to manipulate the URL returned by the API (or bypass protections via DNS rebinding) to scan or access internal infrastructure.
**Learning:** Using simple IP validation before a standard `requests.get` is insufficient because `requests` natively follows redirects and re-resolves hostnames, leaving it open to TOCTOU (Time-of-Check to Time-of-Use) DNS rebinding attacks. Monkey-patching global connection functions is dangerous and thread-unsafe in concurrent environments like Django. A robust mitigation requires creating a custom `requests.adapters.HTTPAdapter` that explicitly uses a pre-validated IP to establish the socket connection, entirely avoiding a second DNS resolution during the actual fetch while maintaining SNI functionality.
**Prevention:** Always validate resolved IP addresses against restricted ranges (private, loopback, multicast, etc.) before fetching external URLs. Ensure that the exact validated IP is used for the network connection (e.g., via a custom HTTPAdapter) to prevent DNS rebinding bypasses. Explicitly handle redirects manually and re-validate each subsequent URL's IP.
