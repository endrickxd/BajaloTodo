## 2024-10-28 - [CRITICAL] Prevent SSRF in User-Controlled URL Downloads
**Vulnerability:** The application uses `requests.get()` to download media URLs returned by the Cobalt API or directly requested by the user. If an attacker crafts a malicious URL or if a Cobalt instance is compromised/spoofed to return an internal/private IP, `requests.get()` would fetch that resource, resulting in Server-Side Request Forgery (SSRF) and allowing access to internal services.
**Learning:** Naively fetching unverified external URLs without validating their destination IPs can lead to SSRF. Furthermore, default `requests.get()` will follow HTTP redirects, which can be leveraged to bypass initial URL string checks (DNS rebinding and HTTP 3xx redirects to internal infrastructure).
**Prevention:** Always perform application-layer IP validation using a custom `requests.adapters.HTTPAdapter`. It should override `_new_conn()` in a custom `urllib3.connection.HTTPConnection` class. This ensures hostnames are explicitly resolved via `socket.getaddrinfo`, and any resolved IP addresses are verified against private, loopback, link-local, and multicast ranges before explicitly connecting to the validated IP. Additionally, redirect logic should be manually managed with `allow_redirects=False` to ensure every intermediate location is subject to the same strict validation check, preventing redirect-based bypasses.
