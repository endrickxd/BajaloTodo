## 2024-11-05 - Critical SSRF in Cobalt Downloader Fallback
**Vulnerability:** A critical Server-Side Request Forgery (SSRF) vulnerability was discovered in `downloader/utils.py`. When downloading media via the Cobalt API fallback (`download_via_cobalt`), the application accepts a `download_url` from external API responses and fetches it using `requests.get()` without any validation. An attacker could potentially compromise an external Cobalt instance or spoof responses to make the Django application issue HTTP requests to internal, restricted, or loopback network addresses (e.g., `http://127.0.0.1`, AWS metadata endpoints).
**Learning:** External API responses containing URLs meant to be fetched by the application must never be blindly trusted. Standard `requests.get()` blindly follows redirects and resolves hostnames via the system DNS, which can be bypassed by DNS rebinding attacks or custom DNS records resolving to internal IPs.
**Prevention:** Implement rigorous SSRF mitigation at the network level before making outbound requests. This includes manually handling HTTP redirects (`allow_redirects=False`) to validate each hop's destination. Furthermore, use a custom `requests.adapters.HTTPAdapter` overriding `_new_conn()` in `urllib3.connection.HTTPConnection` to resolve the hostname and assert that the resulting IP addresses are not part of private, loopback, link-local, multicast, or unspecified ranges before the socket is created.
