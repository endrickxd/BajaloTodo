## 2024-10-19 - SSRF Vulnerability in Cobalt Fallback Downloader
**Vulnerability:** The application fetches media directly from a URL provided by external Cobalt APIs using `requests.get` without validating the host. If a malicious or compromised Cobalt instance returns a local/internal network URL (e.g., `http://169.254.169.254` or `http://127.0.0.1`), the application acts as a proxy, resulting in Server-Side Request Forgery (SSRF).
**Learning:** Application-layer validation of parsed endpoints from untrusted sources is critical before fetching them. Also, standard requests modules follow redirects automatically by default, potentially bypassing initial URL validations (like DNS rebinding attacks to some extent, though rebinding still applies TOCTOU). Always handle redirects manually and validate each step, explicitly rejecting private/multicast/loopback addresses resolved via `socket.getaddrinfo`.
**Prevention:** Implement a robust validation function to parse the hostname and resolve it strictly to IPv4/IPv6 addresses, rejecting restricted networks. Wrap `requests.get` to `allow_redirects=False` and manually iterate and re-validate subsequent locations. Ensure `ipaddress` correctly checks against IPv4-mapped IPv6 formats.
