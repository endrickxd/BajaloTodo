## 2025-02-12 - SSRF Vulnerability via Cobalt fallback URL
**Vulnerability:** The `download_via_cobalt` function in `downloader/utils.py` uses `requests.get` to fetch the file specified by `download_url`, which is obtained from the response of an external Cobalt instance. A malicious Cobalt instance or an attacker who controls the input URL could cause the Cobalt instance to return an internal IP or local loopback address as the `download_url`. Since there's no validation of `download_url`, this allows a Server-Side Request Forgery (SSRF) attack.
**Learning:** External API responses containing URLs to be subsequently fetched by the server must be strictly validated before usage to prevent SSRF, even if the API itself seems trustworthy (as the URL might resolve to an internal IP). Relying solely on `requests.get()` without an HTTP adapter that validates resolved IPs opens up the risk of TOCTOU (Time-of-Check to Time-of-Use) DNS rebinding attacks.
**Prevention:** Always use a custom HTTP adapter (like `urllib3` `HTTPConnection` override) that resolves the hostname to an IP address and blocks private, loopback, link-local, and multicast IP ranges *before* initiating the socket connection. Handle redirects manually to re-validate IPs on each redirect.
