## 2026-08-28 - [Fix hardcoded secrets and debug configuration in Django settings]
**Vulnerability:** The Django project's `settings.py` contained hardcoded sensitive information, specifically the `SECRET_KEY`, and had `DEBUG` set to `True`, which can expose stack traces and other internal details. `ALLOWED_HOSTS` was also overly permissive (['*']).
**Learning:** This is a common security issue where default or development settings are accidentally left in place for production or checked into version control. Django's `SECRET_KEY` must be kept secret to prevent tampering with sessions, password resets, and other cryptographic functions. Having `DEBUG = True` in production is a critical risk as it exposes detailed error pages, which can leak sensitive code or configurations to attackers. Setting `ALLOWED_HOSTS` to `['*']` leaves the application vulnerable to HTTP Host header attacks.
**Prevention:** Always use environment variables to manage sensitive configurations and environment-specific settings (like `DEBUG` and `ALLOWED_HOSTS`). Default configurations should fall back to secure values or the application should refuse to start if critical environment variables are missing.
