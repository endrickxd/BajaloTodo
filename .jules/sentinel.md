## 2024-10-06 - [CRITICAL] Fix SSRF vulnerability in Cobalt API downloads
**Vulnerability:** The `download_via_cobalt` function in `downloader/utils.py` blindly trusts the `url` returned by external Cobalt API instances and passes it to `requests.get()` without any validation. This allows a malicious or compromised Cobalt instance to return a URL pointing to internal network addresses (e.g., `http://169.254.169.254` or `http://127.0.0.1`), leading to Server-Side Request Forgery (SSRF).
**Learning:** The application needs application-layer IP validation to mitigate SSRF. Using `socket.getaddrinfo` is a robust way to resolve hostnames to IP addresses, ensuring IPv6 and CDNs are handled correctly. However, even with IP validation, there's an inherent Time-of-Check to Time-of-Use (TOCTOU) DNS rebinding limitation, where the underlying IP may change between the validation check and the actual HTTP request. In addition, manual redirect handling is required since `requests.get()` follows redirects by default which could bypass the initial URL validation.
**Prevention:** Always validate external URLs (especially those obtained from third-party APIs) against restricted IP ranges (private, loopback, link-local, multicast, unspecified) before making HTTP requests. Use `socket.getaddrinfo` for resolution, and implement manual redirect handling with `allow_redirects=False` in HTTP libraries to ensure redirects are also validated.
