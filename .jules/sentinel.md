## 2024-10-27 - [SSRF Mitigation in External Data Fetching]
**Vulnerability:** The application fetches media using external API tunnels which might redirect or supply unverified URLs. Direct usage of `requests.get` is susceptible to Server-Side Request Forgery (SSRF), allowing external actors to make requests to internal infrastructure on the server's behalf.
**Learning:** Preventing SSRF requires verifying hostnames at the IP level. There is a Time-of-Check to Time-of-Use (TOCTOU) risk where DNS records can change between validation and retrieval (DNS rebinding). Furthermore, when checking IPs, one must consider IPv4-mapped IPv6 addresses, which can bypass generic private IP checks if not explicitly resolved using `getattr(ip_obj, 'ipv4_mapped', None)`. Default `requests.get` redirect following bypasses initial URL checks, so redirects must be managed manually with intermediate closing to avoid resource leaks.
**Prevention:** Always use robust hostname resolution (e.g., `socket.getaddrinfo`), extract IPv4 addresses to catch mapped addresses, manually handle redirects checking safety at each step, and enforce bounds on maximum redirects.
