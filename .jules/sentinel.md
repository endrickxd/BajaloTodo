## 2025-01-20 - [SSRF Bypass via DNS Rebinding and IPv4-Mapped IPv6]
**Vulnerability:** External URLs returned by third-party APIs (like Cobalt) were downloaded via `requests.get` without any validation. This exposed the server to SSRF (Server-Side Request Forgery) attacks where an attacker could force the server to make requests to internal infrastructure (e.g., AWS metadata at `169.254.169.254`, `localhost`, or private IPs). Additionally, simply checking the hostname could be bypassed by DNS rebinding, or loopback IPs could be mapped inside IPv6 addresses.
**Learning:** Checking the domain alone is insufficient for SSRF mitigation because a domain can resolve to an internal IP (either immediately or via a subsequent request, known as DNS rebinding). Moreover, Python's `ipaddress` library may treat certain IPv4-mapped IPv6 addresses differently unless explicitly checked via `getattr(ip, 'ipv4_mapped', None)`. Default redirect behavior in requests (`allow_redirects=True`) can also bypass initial URL validation.
**Prevention:** Always use `socket.getaddrinfo` to resolve all possible IPs for a domain and check them against private, loopback, link-local, multicast, and unspecified ranges. Handle HTTP redirects manually (`allow_redirects=False`) and validate the URL on each redirect step. Finally, ensure proper extraction of IPv4 addresses from IPv6 mappings during validation.
