## 2024-05-20 - SSRF in download_via_cobalt via redirects
**Vulnerability:** Server-Side Request Forgery (SSRF). The application fetched data from Cobalt API endpoints which then returned a `download_url` (status tunnel/redirect/picker). This `download_url` was passed directly to `requests.get()` without any validation. An attacker could manipulate the response from a fake Cobalt instance or exploit a flaw in a real one to provide an internal IP address or malicious URL, leading to SSRF.
**Learning:** `requests.get()` by default will follow redirects and doesn't inherently protect against DNS rebinding or internal IP access. Any URL derived from an external service must be treated as untrusted user input, even if the initial service call was over a hardcoded URL list (since the response data itself might be malicious or hijacked).
**Prevention:** Implement application-layer SSRF protections using a custom `requests.adapters.HTTPAdapter` overriding `urllib3`'s `_new_conn()` to resolve hostnames and block connections to private, loopback, link-local, multicast, or unspecified IP addresses. This mitigates TOCTOU DNS rebinding issues. Do not just validate the hostname; validate the resolved IPs.
