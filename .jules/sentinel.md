## 2024-10-18 - [SSRF Protection with Application-Layer IP Validation]
**Vulnerability:** The application was fetching media resources via `requests.get()` and hitting external API endpoints using `requests.post()` using arbitrary URLs controlled by external systems (like Cobalt's API responses) without validating the underlying IP addresses. This allowed potential SSRF by resolving hostnames to internal network resources.
**Learning:** While implementing IP validation checks (blocking private, loopback, link-local, multicast, etc.) using `socket.getaddrinfo`, it is critical to acknowledge the inherent Time-of-Check to Time-of-Use (TOCTOU) DNS rebinding limitation. Because the DNS resolution during validation is decoupled from the DNS resolution performed by the `requests` library when it fetches the URL, an attacker could manipulate the DNS response to return a safe IP during validation and an internal IP during retrieval.
**Prevention:** The initial layer of defense implemented validates IP ranges and explicitly extracts IPv4 addresses from IPv4-mapped IPv6 ones (e.g. `::ffff:127.0.0.1`) using `getattr(ip, 'ipv4_mapped', None)`. Furthermore, manual redirect handling explicitly validates each hop in the redirect chain to prevent bypassing the initial validation. Future architectural enhancements should consider network-level egress filtering or enforcing resolution pinning to fully neutralize DNS rebinding attacks.
