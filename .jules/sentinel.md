## 2024-03-24 - SSRF vulnerability in Cobalt fallback
**Vulnerability:** The `download_via_cobalt` function fetched arbitrary URLs parsed from external Cobalt API responses using standard `requests.get()` without proper validation. This could lead to a Server-Side Request Forgery (SSRF) vulnerability.
**Learning:** External API responses containing URLs to fetch should be treated with the same level of suspicion as direct user input. Proper hostname resolution and filtering of internal/restricted IPs must be performed to prevent attackers from using the backend to probe internal infrastructure.
**Prevention:** Implement an application-level SSRF mitigation by overriding `urllib3`'s `_new_conn()` method. Ensure DNS resolution resolves the hostname to its IP first, validate the IP address against internal/restricted ranges (e.g., using `socket.getaddrinfo` and checking against `ipaddress` properties), and connect directly to the validated IP to prevent TOCTOU (DNS rebinding) attacks. Ensure `allow_redirects=False` is used, and redirects are manually handled securely.
