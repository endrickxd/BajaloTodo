## 2024-05-15 - Prevent SSRF via IP Validation in `requests`
**Vulnerability:** The application was making network requests to unverified URLs derived from user input without checking the resolved IP addresses. This left the system vulnerable to Server-Side Request Forgery (SSRF) and DNS rebinding attacks.
**Learning:** Standard library `requests.get` defaults to resolving hostnames immediately before establishing the connection. To prevent SSRF reliably, we must create a custom HTTP adapter that overrides `urllib3`'s `HTTPConnection._new_conn()`. Inside this method, we can perform DNS resolution using `socket.getaddrinfo`, validate the resulting IPs against private/loopback/link-local ranges (accounting for IPv4-mapped IPv6), and directly establish the socket connection using the validated IP. We must also manage redirects manually to prevent bypassing the initial validation.
**Prevention:** Use a custom connection factory or an established security library to validate IP addresses before connecting, rather than solely relying on hostname or URL validation.
