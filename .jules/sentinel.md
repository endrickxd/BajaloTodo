## 2024-10-02 - [CRITICAL] Prevent SSRF in Cobalt Download URL
**Vulnerability:** The application fetches a `download_url` from the Cobalt API (which may return a tunnel/redirect URL). It then performs a `requests.get(download_url, stream=True, timeout=60)` without validating the `download_url`. This creates a blind SSRF vulnerability where an attacker controlling the Cobalt API response or using DNS rebinding could force the server to make requests to internal services (e.g., cloud metadata endpoints or internal databases).
**Learning:** External API responses containing URLs must be treated as untrusted user input. Using `requests.get()` directly on such URLs without hostname validation allows SSRF. Additionally, default redirect following in `requests` can bypass initial validation.
**Prevention:** Always parse and validate the hostname of external URLs, resolve the IP using `socket.getaddrinfo`, and ensure it doesn't fall into private, loopback, link-local, multicast, or unspecified ranges. Use manual redirect handling (`allow_redirects=False`) to re-validate each redirect URL.
