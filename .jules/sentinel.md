## 2024-11-02 - SSRF Vulnerability in Cobalt Fallback
**Vulnerability:** The application was vulnerable to SSRF (Server-Side Request Forgery) in `downloader/utils.py`. When falling back to Cobalt instances for media extraction, it blindly followed external redirects and parsed external URLs, returning them to the user. Later, the app downloaded the file using `requests.get(download_url, stream=True)` without validating if the IP address it was resolving to belonged to internal infrastructure.
**Learning:** External API data used for fetching files internally must be heavily scrutinized. Unvalidated URL fetches can result in fetching loopback (127.0.0.1) or internal IPs, bypassing perimeter security and exposing internal services. Standard URL validation is not enough; DNS Rebinding protection is required.
**Prevention:** Implement `SafeHTTPAdapter` that explicitly resolves hostnames and validates that they do not point to private or internal IP addresses (loopback, private subnets, link-local, multicast) before making socket connections. Overriding `urllib3`'s connection logic prevents time-of-check to time-of-use (TOCTOU) DNS rebinding issues.
