## 2024-05-24 - SSRF vulnerability and mitigation regarding application-layer IP validation.
**Vulnerability:** The application was downloading files using `requests.get()` from URLs provided by an external API (Cobalt) without proper validation, leading to a Server-Side Request Forgery (SSRF) vulnerability. This could allow an attacker to send requests to internal infrastructure or read local files.
**Learning:** `requests.get()` follows redirects by default, which can bypass initial URL validation. Furthermore, validating IPs directly from URLs is insufficient due to Time-of-Check to Time-of-Use (TOCTOU) DNS rebinding limitations. The underlying IP may change between validation and retrieval.
**Prevention:** Always resolve hostnames to IP addresses using robust methods like `socket.getaddrinfo` before checking if they fall into restricted ranges. Implement manual redirect handling (`allow_redirects=False`) in a loop, explicitly closing intermediate responses and re-validating each redirect URL (resolved using `urllib.parse.urljoin`) to prevent SSRF bypasses via redirects. Document this TOCTOU limitation in security journals.
