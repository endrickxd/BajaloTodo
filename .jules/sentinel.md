## 2024-05-24 - SSRF Mitigation via Custom HTTPAdapter (DNS Rebinding)
**Vulnerability:** The application fetches external URLs returned by Cobalt API using `requests.get()`. A malicious Cobalt API could return a URL pointing to internal infrastructure (e.g., `http://127.0.0.1/admin`). Naively parsing the URL and checking its IP before fetching is vulnerable to Time-Of-Check to Time-Of-Use (TOCTOU) DNS rebinding attacks because the IP address could change between validation and the actual HTTP request.
**Learning:** Overriding `HTTPAdapter` and `HTTPConnection._new_conn` to validate IP addresses and force socket creation using the validated IP address ensures that the same IP is used for both validation and the HTTP request. This prevents DNS rebinding attacks. Custom redirect handling is also required since default `requests` redirect handling may bypass the custom adapter or re-resolve DNS implicitly if not careful.
**Prevention:** Always use a custom HTTPAdapter that overrides `_new_conn` to enforce IP validation at socket creation time when fetching user-supplied or external API-supplied URLs. Avoid naive URL parsing for SSRF validation. Handle redirects manually to ensure each redirect URL is properly validated.
