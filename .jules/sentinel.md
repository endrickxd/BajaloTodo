## 2025-02-18 - Prevent SSRF in `requests.get` using a custom `requests.adapters.HTTPAdapter`
**Vulnerability:** The application was using `requests.get()` to fetch external media files (like `download_url` in `downloader/utils.py`) without proper validation. This exposes the application to Server-Side Request Forgery (SSRF) if the downloaded URL points to internal IP addresses or private infrastructure.
**Learning:** Preventing SSRF with `requests` requires correctly resolving hostnames to IP addresses using robust methods like `socket.getaddrinfo`, and strictly verifying that the resolved IP does not fall within loopback, link-local, private, multicast, or unspecified ranges. Because `requests.get()` follows redirects by default, it is essential to disable this behavior and handle redirects manually so that we validate each destination sequentially, ensuring no bypass via redirects (e.g. redirecting to `127.0.0.1`). Implementing application-layer IP validation should be done using a custom `HTTPAdapter` overriding `urllib3`'s `HTTPConnection._new_conn()`, preventing DNS rebinding. Replacing the URL's hostname with the validated IP breaks HTTPS/SNI certificate validation.
**Prevention:** Always validate resolved IP addresses (via DNS resolution) for URLs used in `requests.get` calls when dealing with user-supplied or externally-fetched URLs. Create a custom `requests.adapters.HTTPAdapter` overriding `_new_conn()` instead of dynamically monkey-patching global connection functions to avoid thread-safety issues. Explicitly handle manual HTTP redirects in a loop to ensure validation on each redirection.
