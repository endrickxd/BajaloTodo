## 2024-10-03 - [SSRF in external API callbacks]
**Vulnerability:** The application fetches media files based on URLs provided by a third-party service (Cobalt API). The `download_via_cobalt` function used `requests.get()` which defaults to following redirects. A malicious API or a man-in-the-middle attacker could redirect the download request to internal infrastructure (e.g., `127.0.0.1`, `169.254.169.254`), leading to Server-Side Request Forgery (SSRF).
**Learning:** Even when the initial URL is validated, `requests` following redirects can bypass the validation. Furthermore, validation based on simple string checks or DNS resolution can be bypassed (e.g., DNS rebinding).
**Prevention:** Implement strict manual redirect handling (`allow_redirects=False` in `requests.get`) and validate each redirect URL. Validation must resolve hostnames to IP addresses using robust methods (like `socket.getaddrinfo`) and explicitly check against restricted ranges (private, loopback, link-local, multicast, etc.) using `ipaddress`.
