## 2024-05-24 - [Mitigate SSRF vulnerability in Cobalt API client]
**Vulnerability:** The application blindly follows external Cobalt API redirects via `requests.get(download_url, stream=True)` when fetching files. An attacker controlling the Cobalt instance (or a MITM if one was plain HTTP) could return a URL pointing to internal infrastructure (e.g., `http://127.0.0.1:8000`), forcing the Django server to perform unauthorized internal requests (SSRF).
**Learning:** `requests.get` defaults to following redirects. When dealing with third-party APIs that return URLs for subsequent fetching, URL validation must handle redirects explicitly to prevent bypassing initial checks. DNS rebinding/A-record tricks must also be thwarted by resolving the host to an IP and checking it against private ranges before fetching.
**Prevention:** Implement custom redirect handling using `allow_redirects=False` in requests, combined with robust IP address checks using `socket.getaddrinfo` and `ipaddress` for every URL in the redirect chain before making the actual request. Ensure inline security comments clarify this mitigation.
