## 2024-10-28 - SSRF in user-controlled URL fetch
**Vulnerability:** The application took a URL returned by an external API (Cobalt) and fetched it using `requests.get` without any IP validation. If an attacker could control or spoof the Cobalt API's response (or if a Cobalt instance was malicious), they could direct the server to fetch resources on internal networks (like `http://127.0.0.1` or AWS metadata endpoints).
**Learning:** `requests.get` automatically follows redirects and resolves hostnames without exposing IP information directly. It's difficult to properly secure without hooking deeply into the connection mechanism to validate the IP address right before the socket is created. Application-layer IP validation can be bypassed using DNS rebinding if the IP is checked, and then a new connection is made which re-resolves the hostname.
**Prevention:** Override the connection process in `urllib3` by creating custom `HTTPConnection` and `HTTPSConnection` classes, overriding `_new_conn`, and performing the DNS resolution and IP validation *there*. Then use this custom connection logic via a custom `HTTPAdapter` hooked into the `requests.Session`.
