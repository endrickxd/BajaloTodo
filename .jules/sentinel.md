## 2024-10-29 - Server-Side Request Forgery in Cobalt instance redirect
**Vulnerability:** The application directly fetched a download URL from the Cobalt instance fallback (`downloader/utils.py`, line 90) using `requests.get()` without any validation. Because the Cobalt instance is an external service, if it were compromised or malicious, it could return an internal URL (like `http://169.254.169.254/latest/meta-data/` or `http://127.0.0.1/admin`), leading to a Server-Side Request Forgery (SSRF) attack against our application server.
**Learning:** External services and APIs can sometimes act as proxies or redirect mechanisms that feed input directly into outbound HTTP requests. Any URL fetched dynamically from an external source must be validated, even if the primary usage is just downloading files. Specifically, DNS rebinding needs to be considered when validating IPs in Python, which is why a custom `requests.adapters.HTTPAdapter` overriding `urllib3`'s connection logic is needed instead of naive URL parsing.
**Prevention:** Always validate all outbound URLs retrieved dynamically. Use `socket.getaddrinfo` to resolve IPs and check for private, loopback, link-local, multicast, or unspecified IP ranges. To prevent Time-Of-Check-To-Time-Of-Use (TOCTOU) DNS rebinding attacks, bind the HTTP connection directly to the validated IP instead of resolving it again.
