## 2024-10-06 - [Fix SSRF vulnerability in external API fetching]
**Vulnerability:** The application fetches URLs returned by an external API (Cobalt) using `requests.get()` without validating if those URLs resolve to internal, loopback, or private IP addresses. This allows Server-Side Request Forgery (SSRF) where the external API could trick the server into making requests to internal infrastructure (e.g., cloud metadata services or internal APIs).
**Learning:** `requests.get()` follows redirects by default, meaning that even if the initial URL is safe, a redirect could bypass the validation and point to an internal resource. Additionally, validating hostnames via DNS resolution is subject to Time-of-Check to Time-of-Use (TOCTOU) limitations, like DNS rebinding. Resolving the IP explicitly with `socket.getaddrinfo` handles IPv6 and CDN variations better than `gethostbyname`.
**Prevention:** Implement strict application-layer IP validation on all outbound requests triggered by external input. Explicitly resolve hostnames using `socket.getaddrinfo`, and ensure no resolved IP falls into private, loopback, link-local, multicast, or unspecified ranges. Manually handle HTTP redirects (`allow_redirects=False` in `requests.get`), close intermediate responses, resolve relative URLs safely using `urllib.parse.urljoin`, and re-validate every redirect URL against the safe IP ranges before proceeding. Note the inherent TOCTOU DNS rebinding limitation when performing application-layer IP validation.
