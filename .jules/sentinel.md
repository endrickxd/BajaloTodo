## 2023-10-27 - SSRF in external API download handler
**Vulnerability:** The application was vulnerable to Server-Side Request Forgery (SSRF) when downloading files from the Cobalt API fallback (`downloader/utils.py`). The `requests.get()` call blindly fetched whatever URL was returned by the external Cobalt instances (via `download_url`) without validation. A malicious or compromised Cobalt instance could return a URL pointing to internal network infrastructure (e.g., `http://169.254.169.254/latest/meta-data/` on AWS, or `http://127.0.0.1/admin`), and the backend server would make the request, effectively proxying the attack.
**Learning:** Even when integrating with seemingly trusted external APIs (like the hardcoded Cobalt instances), any URLs returned by those APIs and subsequently fetched by the backend must be strictly validated. The default `requests.get()` behavior also follows redirects, which can bypass initial URL validation if not handled manually.
**Prevention:** Always validate hostnames to IP addresses using robust methods like `socket.getaddrinfo` before checking if they fall into private, loopback, link-local, multicast, or unspecified ranges. When implementing manual redirect handling (e.g., `allow_redirects=False`), explicitly resolve relative redirect URLs using `urllib.parse.urljoin`, check each redirect target, and close intermediate responses.
