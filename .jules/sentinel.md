## 2024-10-11 - [SSRF Mitigation in External File Retrieval]
**Vulnerability:** The application fetches media files from external URLs returned by the Cobalt API directly using `requests.get()` without any validation of the URL's hostname or IP address.
**Learning:** This introduces a Server-Side Request Forgery (SSRF) vulnerability. An attacker or a compromised Cobalt API instance could return a URL pointing to internal infrastructure (e.g., `http://169.254.169.254/` for AWS metadata or `http://127.0.0.1/` for local services), forcing the application server to make requests to those internal endpoints. When mitigating SSRF via application-layer IP validation (e.g., `socket.getaddrinfo`), there is an inherent Time-of-Check to Time-of-Use (TOCTOU) DNS rebinding limitation, as the underlying IP may change between validation and retrieval.
**Prevention:** Implement strict URL validation before fetching external resources. This involves parsing the URL, resolving its hostname to IP addresses using robust methods like `socket.getaddrinfo`, and rejecting the URL if any resolved IP falls into restricted ranges (private, loopback, link-local, multicast, or unspecified). Additionally, handle redirects manually to ensure each subsequent URL in the chain is similarly validated.
