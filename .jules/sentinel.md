## 2024-09-30 - SSRF Mitigation in External API Fallbacks
**Vulnerability:** The application previously blindly fetched URLs returned by external API services (Cobalt instances) using `requests.get` without validating the destination. Since `requests.get` follows redirects by default, this could allow an attacker to bypass initial URL checks and force the server to make requests to internal network services or cloud metadata endpoints.
**Learning:** When interacting with external APIs that return URLs for subsequent fetching, those URLs must be strictly validated. Furthermore, because redirects can point to arbitrary locations, redirect handling must be done manually (`allow_redirects=False`) and each intermediate URL must be validated against a strict IP-based blocklist (private, loopback, link-local, etc.) before the request is issued.
**Prevention:** Implement a rigorous `is_safe_url` function that resolves hostnames via `socket.getaddrinfo` and rejects any URL resolving to a restricted IP space. Apply this validation to the initial URL and within a manual redirect loop using `urllib.parse.urljoin` to securely handle relative redirects.
