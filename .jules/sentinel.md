## 2024-09-27 - SSRF Mitigation via Cobalt API Download Endpoint
**Vulnerability:** The `requests.get` call in `download_via_cobalt` downloaded files from a URL returned by an external API (Cobalt) without verifying if the target hostname resolved to private or internal IP addresses (e.g., 127.0.0.1, AWS metadata endpoint), leading to potential SSRF (Server-Side Request Forgery). The default behavior of `requests.get` also blindly followed redirects, creating an bypass for simple pre-request validations.
**Learning:** Resolving hostnames to IP addresses using `socket.getaddrinfo` and checking them against private ranges using `ipaddress` provides robust defense against DNS rebinding or custom DNS A records. Furthermore, managing redirects manually with `allow_redirects=False` is critical when validating external URLs in a loop, ensuring every redirect hop is vetted against internal network boundaries before being followed.
**Prevention:** Always explicitly validate third-party-provided URLs down to their resolved IPs before initiating requests, and never blindly allow HTTP clients to follow redirects when SSRF is a concern. Integrate explicit redirect handling and IP validation loops in all data fetching functions.
