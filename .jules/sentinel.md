## 2024-05-18 - SSRF Vulnerability in File Downloading
**Vulnerability:** The application fetches external URLs returned by the Cobalt API directly using `requests.get()` without proper SSRF validation. This could allow an attacker to bypass DNS and access internal infrastructure if the Cobalt API returns a local IP, or via a malicious payload if DNS rebinding is utilized.
**Learning:** Standard HTTP libraries like `requests` implicitly follow redirects and resolve DNS without built-in SSRF protections. Validating URLs solely using regular expressions or initial DNS resolution leaves the system vulnerable to DNS rebinding (TOCTOU attacks).
**Prevention:** Override the underlying `urllib3` connection classes (`HTTPConnection`) and pool managers to ensure the socket connects strictly to the IP address validated immediately prior to connection, avoiding re-resolution and DNS rebinding attacks. Also, implement strict loopback and private IP checks, and manually handle HTTP redirects to ensure every redirected URL goes through the same rigorous check.
