## 2024-11-20 - SSRF Vulnerability in Cobalt Download Pipeline
**Vulnerability:** The application fetches external media endpoints provided by the Cobalt API directly using `requests.get()` in `download_via_cobalt`. An attacker controlling or spoofing the Cobalt API response could return URLs pointing to internal infrastructure (e.g., `http://169.254.169.254`, `http://127.0.0.1`, or local Docker networks), leading to Server-Side Request Forgery (SSRF) and potential compromise of internal systems or cloud metadata.
**Learning:** External API responses containing URLs to fetch must be treated as untrusted input. `requests.get()` by default transparently follows redirects, potentially bypassing initial URL validation if redirects point back to local resources.
**Prevention:** Implement strict URL validation resolving hostnames to IP addresses with `socket.getaddrinfo`, denying private, loopback, multicast, or unspecified ranges. Manually handle redirects (`allow_redirects=False`) and validate the `Location` header (using `urllib.parse.urljoin` for relative URLs) for each step of the redirect chain to prevent DNS rebinding or redirect-based SSRF bypasses.
