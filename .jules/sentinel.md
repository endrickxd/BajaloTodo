## 2024-10-15 - Application-Layer SSRF Validation and TOCTOU DNS Rebinding
**Vulnerability:** Server-Side Request Forgery (SSRF) when fetching external URLs provided by user input or third-party APIs.
**Learning:** When mitigating SSRF using application-layer IP validation (e.g., `socket.getaddrinfo` to check if an IP is private), there is an inherent Time-of-Check to Time-of-Use (TOCTOU) DNS rebinding limitation. The underlying IP associated with a hostname may change between the validation step and the actual data retrieval step. Additionally, when using `ipaddress` to validate IPs, IPv4-mapped IPv6 addresses (e.g., `::ffff:127.0.0.1`) can bypass checks if not explicitly mapped back to IPv4 using `ipv4_mapped`.
**Prevention:** Always resolve hostnames to IP addresses using robust methods like `socket.getaddrinfo` and iterate through all returned IPs. Explicitly extract mapped IPv4 addresses using `ip.ipv4_mapped`. Be aware that true protection against DNS rebinding often requires network-level controls (e.g., egress filtering) or locking down the DNS resolution mechanism at the HTTP client level.
