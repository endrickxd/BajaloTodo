## 2024-05-24 - [CRITICAL] Prevent SSRF in Cobalt API Download Callbacks
**Vulnerability:** The application fetches video/audio download URLs via the external Cobalt API and then blindly requested those URLs using `requests.get` with default redirect following. A malicious Cobalt server could return a redirect to internal network infrastructure (e.g., `169.254.169.254` or `127.0.0.1`), causing an SSRF.
**Learning:** SSRF mitigation must be applied not just to direct user inputs, but also to URLs fetched from external APIs, as those endpoints can be compromised or spoofed. Also, `socket.getaddrinfo` validates IP addresses, but it has a Time-of-Check to Time-of-Use (TOCTOU) DNS rebinding limitation because the underlying IP might change between the DNS validation and the actual HTTP request.
**Prevention:** Implement `allow_redirects=False` in requests to manually follow redirects, and use `socket.getaddrinfo` to resolve and check all returned IPs against loopback, private, link-local, multicast, and unspecified ranges prior to fetching each URL in the redirect chain.
