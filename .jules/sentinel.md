## 2024-05-24 - [CRITICAL] Prevent DNS Rebinding SSRF bypass in requests
**Vulnerability:** External user-supplied URLs fetched with `requests.get()` without DNS rebinding protection allowed SSRF. Resolving IPs prior to fetching was insufficient because `urllib3` inside `requests` re-resolves the hostname, creating a Time-Of-Check-Time-Of-Use (TOCTOU) DNS rebinding vulnerability.
**Learning:** Standard SSRF protection of checking IPs before making the request fails against DNS rebinding when using default `requests` behavior, because the target hostname is re-resolved. Setting the URL to the resolved IP instead of the hostname breaks HTTPS/SNI. The only robust way to protect `requests` against DNS rebinding while supporting HTTPS is to implement a custom `requests.adapters.HTTPAdapter` overriding `urllib3.connection.HTTPConnection._new_conn()` to securely bind the socket directly to the validated IP.
**Prevention:** Implement a custom `HTTPAdapter` and `HTTPConnection` classes that use `socket.getaddrinfo` to resolve the hostname, iterate through returned IPs to reject any restricted IP ranges, and directly create the connection using `urllib3.util.connection.create_connection` with the validated IP. Ensure that the socket uses this IP without calling `super()._new_conn()` which would re-resolve the host. Additionally, handle HTTP redirects manually (`allow_redirects=False`) while checking intermediate URLs using `urllib.parse.urljoin`, rather than relying on default `requests` redirect handling which skips the custom adapter's pool assignment for the redirect targets in some versions/configurations.
