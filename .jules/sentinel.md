## 2024-05-18 - [Fix Hardcoded Secrets in Django Settings]
**Vulnerability:** Django settings like `SECRET_KEY`, `DEBUG`, and `ALLOWED_HOSTS` were hardcoded directly in `videodownloader_project/settings.py`. This exposes sensitive keys if the codebase is shared or made public, and could lead to deploying to production with `DEBUG = True`, exposing stack traces and sensitive environment details to end-users.
**Learning:** Hardcoded configuration values are a significant security risk, especially for a framework's primary secret key and debug mode. Relying solely on hardcoding for local development makes it too easy to accidentally commit these values and deploy them insecurely. The application architecture did not enforce or encourage the separation of configuration from code.
**Prevention:** Always use environment variables to manage sensitive configuration settings. Provide sensible, secure defaults or fallbacks to ensure local development environments do not break. Specifically for Django, use `os.environ.get('SECRET_KEY', 'fallback')` and properly parse boolean/list environment variables for `DEBUG` and `ALLOWED_HOSTS`.
