## 2024-10-13 - [SSRF in Cobalt Downloader]
**Vulnerability:** The application fetches media using URLs provided by external Cobalt APIs (`download_url`) without any validation, passing them directly to `requests.get()`. This creates an SSRF vulnerability where an attacker or a compromised API could supply an internal IP address (e.g., `169.254.169.254`, `10.0.0.1`), tricking the server into making requests to internal infrastructure or local services.
**Learning:** Application-layer IP validation using `socket.getaddrinfo` and `ipaddress` is necessary to mitigate SSRF when relying on external URLs. However, this approach has an inherent Time-of-Check to Time-of-Use (TOCTOU) limitation, particularly concerning DNS rebinding, because the IP address validated might change before the actual HTTP request is executed by `requests.get()`.
**Prevention:** Always validate all resolved IP addresses against restricted ranges (private, loopback, link-local, multicast, unspecified) before making HTTP requests. Additionally, when using `requests`, set `allow_redirects=False` and manually handle redirects to ensure that all intermediate redirect URLs are also subjected to the same IP validation checks.
