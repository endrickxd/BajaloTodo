## 2024-05-15 - SSRF Vulnerability via External API Download Endpoint
**Vulnerability:** Found a Server-Side Request Forgery (SSRF) vulnerability in `downloader/utils.py`. The `download_via_cobalt` function fetched media from a URL returned by an external API (Cobalt) using `requests.get()` without any validation. An attacker could potentially manipulate the Cobalt instance or man-in-the-middle the response to return a URL pointing to internal infrastructure (e.g., `http://169.254.169.254` for AWS metadata or `http://127.0.0.1` for local services), forcing the application server to make arbitrary requests and potentially leak internal data or access restricted internal services.
**Learning:** `requests.get()` automatically follows redirects by default. Validating the URL *before* passing it to `requests.get()` is insufficient because the initial external URL might redirect to an internal IP address (DNS rebinding or simply a 302 redirect). Both the initial URL and any redirect URLs must be strictly validated.
**Prevention:** Always validate external URLs and their resolved IP addresses against a blacklist of private/reserved IP ranges before making the request. When using libraries like `requests`, disable automatic redirects (`allow_redirects=False`) and handle them manually to validate the `Location` header of each redirect hop. Use robust DNS resolution (`socket.getaddrinfo`) and check all returned IPs, not just the first one.
