## 2024-11-01 - SSRF Vulnerability via Cobalt fallback
**Vulnerability:** The application fetches external URLs provided by users and cobalt responses, then performs an insecure `requests.get` on them (in `downloader/utils.py`). This allows an attacker to make the server perform requests to internal infrastructure (e.g., `127.0.0.1`, AWS metadata), resulting in Server-Side Request Forgery (SSRF).
**Learning:** Even if the URL is extracted from a third-party service like Cobalt, it must be validated before the server accesses it because the third party might return malicious redirects or URLs pointing to private IP addresses. `requests.get` will follow redirects by default and could bypass simple hostname/IP validation if not handled correctly.
**Prevention:** Implement a custom `HTTPAdapter` and `HTTPConnection` for the `requests` library that resolves DNS addresses, rejects private/reserved IP blocks, and prevents DNS rebinding by passing the validated IP address directly to the underlying socket connection. Manually handle redirects to ensure every step in the redirect chain is validated.
