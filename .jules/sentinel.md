## 2024-07-30 - Fix Hardcoded Django SECRET_KEY and DEBUG
**Vulnerability:** Django `SECRET_KEY` and `DEBUG` mode were hardcoded directly in `settings.py`. This poses a critical security risk as the secret key could be exposed if the source code is compromised, allowing for session hijacking, cryptographic signing vulnerabilities, and bypassing CSRF protections. Hardcoded `DEBUG = True` also means debug mode could be accidentally deployed to production, exposing sensitive stack traces, local variables, and environment configuration to end users.
**Learning:** These settings were likely hardcoded for ease of local development, without considering the security implications for production deployment. When securing Django settings like `SECRET_KEY` or `DEBUG` with environment variables, it's crucial to use `os.environ.get()` with the original hardcoded values as fallbacks. This pattern prevents breaking local development and testing environments that rely on these defaults while still allowing for secure configuration in production.
**Prevention:** Always use environment variables for sensitive configuration values, including secrets, API keys, and deployment mode flags (like `DEBUG`). Implement a pattern like `os.environ.get('DJANGO_SECRET_KEY', 'default-unsafe-dev-key')` to maintain a smooth developer experience while ensuring production security. Regularly audit codebases for hardcoded secrets and enforce the use of environment variables during code reviews.
