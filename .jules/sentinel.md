## 2024-10-03 - [SSRF in Third-Party URL Retrieval]
**Vulnerability:** The application was fetching media files using URLs returned from an external API (`Cobalt`) via `requests.get(download_url)` without any prior validation. This exposed the system to a Server-Side Request Forgery (SSRF) vulnerability where an attacker could force the server to issue HTTP requests to internal IP addresses (e.g., `127.0.0.1`, `169.254.169.254`) by having the external API return an internal URL or via HTTP redirects.
**Learning:** Relying purely on the `requests` library's default behavior, which automatically follows HTTP redirects (`allow_redirects=True`), bypasses initial string-based URL validation if the redirect location resolves to an internal IP. Proper validation requires manual redirect handling and DNS-based IP validation at each redirect step to prevent DNS rebinding or malicious redirect paths.
**Prevention:** Always set `allow_redirects=False` in `requests` when fetching untrusted URLs. Implement a custom redirect loop that limits the number of redirects and explicitly resolves the hostname to an IP address using `socket.getaddrinfo`. Iterate over the resolved IPs to verify none fall into private, loopback, multicast, link-local, or unspecified ranges (`ipaddress.ip_address(ip).is_private`, etc.) before making the request. Use `urllib.parse.urljoin` to accurately resolve relative redirect locations.
