## 2024-10-10 - [CRITICAL] Server-Side Request Forgery (SSRF) via Redirect in Cobalt integration
**Vulnerability:** The application blindly fetched URLs returned from external Cobalt APIs using `requests.get()` in `download_via_cobalt`. If a malicious Cobalt instance returned a tunnel URL or a redirect pointing to an internal IP (e.g., `127.0.0.1` or AWS metadata server `169.254.169.254`), the server would fetch it, enabling Server-Side Request Forgery (SSRF).
**Learning:** `requests.get()` follows redirects by default, potentially bypassing initial URL validations. Furthermore, relying on untrusted third-party APIs (like the Cobalt fallback servers) requires strict validation of any URLs they supply before our server initiates a request to them. Even with application-layer IP validation (e.g., resolving the host and checking IP ranges), there is an inherent Time-of-Check to Time-of-Use (TOCTOU) DNS rebinding limitation because the underlying IP may change between the validation (`socket.getaddrinfo`) and the actual retrieval (`requests.get`).
**Prevention:** Always validate hostnames by resolving them to IP addresses using robust methods like `socket.getaddrinfo` and explicitly verify they do not fall into private, loopback, link-local, multicast, or unspecified ranges. When implementing this mitigation with `requests.get()`, set `allow_redirects=False` and handle redirects manually in a loop to ensure every step in a redirect chain undergoes the same rigorous IP validation. Document the TOCTOU DNS rebinding limitation in security considerations.
