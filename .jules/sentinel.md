## 2024-05-18 - [CRITICAL] Fixed SSRF Vulnerability in Cobalt Download Implementation
**Vulnerability:** The application fetches external URLs provided by Cobalt instances via `requests.get()` without validating the underlying IP addresses. Furthermore, `requests.get()` automatically follows redirects by default, enabling an attacker to return a URL pointing to internal infrastructure or an external URL that redirects to internal endpoints.
**Learning:** Preventing SSRF requires deep validation (resolving DNS to explicitly verify IP addresses) combined with strict redirect handling logic (`allow_redirects=False` and manually validating each redirect URL). Validating only the initial URL is insufficient since subsequent redirects can bypass that check. Also, using application-layer validation inherently suffers from Time-of-Check to Time-of-Use (TOCTOU) DNS rebinding limitations, as the IP could change between validation and retrieval. In addition, checking for IPv4 mapped to IPv6 (e.g. `::ffff:127.0.0.1`) is essential when checking the results from `socket.getaddrinfo`.
**Prevention:** Always validate all resolved IPs using `socket.getaddrinfo` (excluding private, loopback, multicast, etc.), explicitly implement manual redirect logic for any fetched URLs, close intermediate redirect responses to prevent resource leaks, and document the remaining TOCTOU risks if network-level firewalls are not enforcing outbound rules.
