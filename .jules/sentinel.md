## 2024-05-15 - SSRF via Cobalt API Fallback
**Vulnerability:** The application fetches media using external Cobalt API endpoints. The API response provides a redirect or direct `download_url`, which was blindly fetched using `requests.get()` without checking if the URL resolved to an internal/private IP address. This introduced a Server-Side Request Forgery (SSRF) vulnerability.
**Learning:** Even when interacting with trusted third-party APIs or external services, URLs returned in their responses must be treated as untrusted user input, as the third-party could be compromised, behave maliciously, or allow open redirects to internal infrastructure.
**Prevention:** Implement strict IP validation using `socket.getaddrinfo` on the hostname of any dynamically generated or retrieved URL before fetching it. When fetching URLs that might redirect, disable automatic redirect following (`allow_redirects=False`) and manually validate every URL in the redirect chain before proceeding.
